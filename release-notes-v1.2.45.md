# RiTrade 1.2.45

_Released 2026-08-04_

### New features

- **You can now delete a single import on its own, and see the imports you have made.** Until now the only way to remove imported data was by date range, which takes everything in the window whatever file it came from. The Danger Zone now offers "One import": find the file in the list, and RiTrade removes what that import wrote and nothing from any other. The list itself is new, because no screen in RiTrade has ever shown you what you have imported: every import, when it ran, which account it went into, newest first, on your own clock. Imports made before RiTrade started recording which fills came from which file cannot be removed precisely, and those rows say so in the place the button would have been rather than offering a control that cannot be honoured.
- **RiTrade records the currency your file or your broker states, and you can state it yourself when neither does.** Every fill used to be stored as US dollars whether or not anything had said so, and once it was in there was no telling a stated currency from an assumed one. Where your file or your broker states a currency, RiTrade reads it. Where nothing does, those fills read "no currency recorded", which is an honest answer rather than a fault. The screen where you match your columns now has a Currency row beside Symbol, Quantity and Price, and leaving it unmatched is honoured just as exactly. Import a file again and the fills that had none get one, and the result screen says how many. Fills you imported before this release keep exactly what they hold: rewriting them would assert an exchange that never took place.
- **Your account card now names the files in your watch folder that did not come in.** Before this, finding out which of your files had not made it meant opening a file explorer and looking. Each one is now named, with the reason in plain words, where it is now, and what it costs you: nothing in those files reached your journal. Where a single question would fix a file (which column is which, which row holds your headings, what date the rows are, a symbol that changed name) the line takes you straight back into that exact file. The line clears itself once the file is dealt with, and a file left stranded stays visible however many clean syncs follow.

### Improvements

- **Every screen now reads one record of what an import did, so they cannot disagree with each other.** Eleven screens used to work out their own answer from whatever numbers were to hand, which is why a fix would land on three of them and miss two, and why a folder run could bring in 479 fills while the account card still read "Ready to bring trades in". The result screen, the folder result, the ingest hub, the account card, the run history and the closing message now all read the same answer. Your account card says the outcome and the counts after every import, including one that found nothing new, so silence stops meaning "probably fine". Imports you start from an account card finally appear in your run history, which they never did.
- **Before an import runs, RiTrade tells you how much of the file this account already holds and what happens to it.** The screen before an import used to announce hundreds of fills flagged for review, and the screen one click later reported the same hundreds skipped with nothing to review. You are now told what is already in your journal down to the fees, what carries different numbers from the copy you hold, and what you removed in an earlier review and is staying removed. Afterwards each of those outcomes is named again with its own count, and the button to review a genuine difference carries the same number the review then lists.
- **Counts say what they are counting.** Rows are lines in your file, fills are the buys and sells RiTrade stored, trades are complete positions, and every figure in the import screens now carries its own noun, the import button included. An account fed whole trades never sees RiTrade's internal count of the halves it splits each one into. Where a number could not be established, nothing is shown rather than a zero that reads as a fact.
- **The screen where you pick a format says what each one reads.** It used to be headed "Confidence" and put the same percentage beside every format you had saved, so a column that looked like evidence carried no information. Each option now says what it reads: everything it needs from your file, or else the columns it leaves out, by name. Formats that leave part of your file out sit under their own heading, so the order on screen explains itself. None has been removed and none is switched off.
- **The confirm screen for a file of finished trades shows how much of it you already hold, and promises the number you actually get.** That screen used to say nothing at all about overlap, so a file that was entirely a re-import looked exactly like a file of brand new trades. It now carries the same pair of figures its sister screens carry, states a measured zero out loud, and says so plainly when it cannot measure rather than showing you a zero it never took. The count on it is now the count that lands, and a line it could not read is named there with its row number and the cell itself.
- **An account set to always use the newest version is warned before it overwrites, not reassured while it does.** That setting deletes your stored copy and the fees recorded against it, and the screen was promising that "nothing is overwritten" at the time. Those accounts are now told plainly, before the import runs, that whatever the file says replaces what is stored, that no dates are compared so an older report wins just as easily as a newer one, and that RiTrade keeps no copy. The result screen then reports how many were replaced, so the one irreversible thing on the screen can be checked afterwards.
- **Deleting tells you what it costs before you press.** Removing an account now names the ledger entries and attached documents that go with it, not just the account and its settings, and the line promising the account survives comes off the screen the moment it stops being true. An account whose rows are all waiting on your decision can finally be reached, instead of reporting nothing to delete and never appearing in the list. Picking accounts that count differently no longer adds their totals into a number that means nothing: each gets its own line in its own unit, and the screen says why there is no combined figure.
- **The hold-time chart reads properly now that a trade runs end to end.** Its bands were drawn back when a trade was a fragment, so the short ones emptied out and everything long piled into one. They are redrawn, and the last band is positions you carried overnight rather than positions held for some number of hours, judged in the market's own timezone so an ordinary day trade on a foreign exchange is not mislabelled by your dashboard's clock. A band holding nothing now says so plainly rather than vanishing or drawing a full bar that read as though every trade in it had lost.
- **When something goes wrong on RiTrade's side, it no longer blames your file in a language nobody speaks.** A failure could put raw technical text on screen and send you off to re-export a file that was perfectly fine. RiTrade now says what it could not do, in its own words, at every step of an import, and the screen around that sentence has stopped contradicting it. A failure RiTrade genuinely cannot explain now names the file and says outright that it cannot tell what happened, instead of confidently telling you to fetch a fresh copy of a file it may never have opened.
- **The import screens read consistently and say the same thing everywhere.** The step where you match columns is called "Match your broker data" wherever you reach it and in the User Guide, one word covers a stock's trading code (symbol), the way into a review of disagreeing fills says how many are waiting and that they are fills, the duplicate setting on an account says what actually happens to a fill that disagrees with one you hold, and the delete panel stops heading its result with "Before you delete". One file is announced in the singular, and a screen reader now hears which account a file badge belongs to.

### Bug fixes

- **A trade you scaled out of counts once, not once per exit.** RiTrade used to record a result every time a sale matched something you had bought, so one position exited in three clips read as three separate results, and a position that lost money could show up as mostly wins. On real data a single trade that lost 4.38 was contributing two wins and one loss to the win rate. A trade is now one position in one symbol from the moment you open it to the moment you are flat, however many fills either side, carrying its exits inside it. Your money has not moved: net, gross and every fee total are identical to the cent. Your trade count drops, your average loss looks bigger because it always was that big, and profit factor, drawdown and the hold-time figures move with it. A total for a date range can differ from before, because a trade now lands wholly in the period it closed in.
- **Broker files that write a timezone or a 12-hour clock now import, and a time RiTrade cannot read is refused out loud.** Times like `08:41:21 +05:30`, `11:00:00 GMT+8` and `10:02:09 AM` could not be read, and instead of failing RiTrade stored your broker's line exactly as it arrived into the column the whole app sorts, filters and groups by. The times looked right because they were your broker's own words, and everything built on top of them was quietly working on text: days did not group, a date filter missed them, your first trade of the day was decided by alphabetical order. Those forms now read correctly and keep the time your broker wrote on the clock. A time RiTrade genuinely cannot read is left out and named, with the row and the cell, on the screen before the import and again after it, so you can fix that line and bring it in.
- **Importing a file again after that change does not give you a second copy of trades you already have.** Once times were read properly, every fill already stored from raw text would no longer have matched the same fill coming back in, so a routine re-import would have added the lot a second time: position sizes doubled, commission doubled, and a P&L wrong in a way that looks like a good month. RiTrade now recognises a fill under the identity it was stored with as well as the one it would have today, through every door, so a re-import of something you hold still changes nothing down to the fees, and a duplicate you removed in an earlier review stays removed. Trades already in your journal keep your broker's raw text as their time until a later release repairs them, so a day can still appear twice, once under each spelling.
- **Two trades that look alike are two trades again, and neither one loses its commission.** Where a broker reports a finished trade as a single line, RiTrade told those lines apart by symbol, opening time, size and the two prices and nothing else. A file holding two genuinely identical trades imported nothing at all and reported that the numbers did not add up. A long and a short agreeing on all five, arriving in two imports, landed as one thing with the first one's commission overwritten and gone, while every screen said the import succeeded. An ordinary scale-out collided with itself and could cost you half the position, take the whole trade out of your P&L, or leave you short shares you never sold. A trade is now told apart by everything its line carries, including which way round it was and when it closed, so two identical trades both land and keep their own costs. Re-importing the same export still changes nothing, even when your broker reorders the rows.
- **Deleting a date range no longer leaves you holding half a trade.** Where the two ends of a broker-reported trade fall on different days, a range covering one of them deleted that end on its own and left a position that never closes: it dropped out of every statistic, took its whole result out of your P&L, and came back as a holding you could not close, with nothing said. Both ends now stay. The screen tells you before you press that part of what you picked reaches outside the dates you gave, and names the dates a wider range would have to cover. The number you agree to is the number that goes. The same rule covers deleting a single past import. What this does not promise is that a delete only ever takes whole trades. What it does promise is that a delete never leaves you a position that cannot close.
- **An ordinary CSV imports on a brand new account instead of being refused.** You could create an account, pick a plain six-column export any spreadsheet would produce, and be told "No data rows found in file." The rows were there: RiTrade had read every one and then discarded them, because it had quietly applied a format saved months earlier on a different account, taught from a completely different file. The quiet version of this was worse than the loud one. A format that reads your symbol, side, size and prices but not one of your fee columns imports every row, reports success, and leaves your profit looking bigger than it was. RiTrade now checks whether a saved format can account for what is actually in your file, fee columns included, and asks you which to use instead of guessing. Nothing is deleted and every saved format stays in the list under its own name.
- **A format that imported nothing is no longer a dead end, and turning one down actually works.** You used to be told the file could not be read, when it could: RiTrade had read every row before the format was applied. That screen now says which format was used, whether you chose it or RiTrade did, how many rows were read, and that none of your trades changed, and it offers you a way on with the same file, either a different format or matching the columns yourself. The link reading "This isn't" followed by a format name used to hand you back the identical screen; it now always moves you on, and a format you turn down is not put in front of you again during that import. "No data rows found in file." is now reserved for a file that genuinely holds none. The same thing happening in a watched folder is filed as a question with a route back into the file, rather than as a file RiTrade could not read.
- **A file you imported once can be imported again, so taking an import back is no longer a one-way door.** Once you had taught RiTrade to read a file of finished trades, the next file of that shape was recognised and then read as though you had taught it nothing, and the screen said your file held nothing to import. The sharp edge was not the second import: you could remove an import cleanly and then find that the only door that would put it back reported an empty file, with nothing having warned you on the way out. RiTrade now reads a file the way you taught it, on every account and through every door, so an import you remove goes back exactly as it came, the same trades and the same costs. Where it genuinely cannot tell the shape of a much older saved layout, it asks you to match the columns once rather than guessing.
- **Cancelling an import no longer locks that file out for good.** Cancel is the button you press when something looks wrong and you want to back out and bring the file in properly. It used to remove the trades and keep the record saying you had already imported the file, so every door refused that file from then on, and the only ways back were renaming it, re-exporting it from your broker, or deleting the account, with nothing telling you any of that. The same file now goes straight back in through either door. A watched folder still treats a cancelled file as handled, so it will not quietly restore the trades you just removed.
- **A file you rescue stops being listed as stranded, and that list stops contradicting itself.** Completing the import from the account card left the line sitting there, because the file was still in the "failed" folder and the list follows the folder. RiTrade now moves the file once its trades are in, renaming rather than overwriting where a file of that name is already there, and the line clears itself with nothing for you to tick off. The paragraph above that list was written for a different kind of file and told you the opposite of what the rows beneath it said. It now says only what is true of everything underneath it, and its count no longer claims attention is needed for a file whose trades are already in.
- **RiTrade no longer suggests which ticker a stock uses now when it cannot tell.** When a file brings in fills you already hold under a different ticker, RiTrade asks which name the stock uses today, and it was marking one Suggested and captioning it "This is the current ticker" on evidence it did not have. On the case that matters most, two exports of the same fills under two names, the mark was decided by which of your files happened to be read second, and broker exports sort newest first, so it pointed at the old name nearly every time. Your answer is saved and never asked again, so one wrong click was permanent. Where there is real evidence the suggestion stays. Where there is none, both tickers are shown even-handedly in alphabetical order and the screen says why. The same two files now produce the same question whichever you import first, where before the reading order could decide whether you were asked at all. That question also names the account the matching fills are in, says your answer applies to every account holding those tickers, and reaching it with the keyboard no longer answers it.
- **A folder run or a broker sync that could not account for your data no longer reports itself as a clean run.** RiTrade already checked at the end of every import whether everything handed over reached your journal, but on those two doors the answer was worked out and thrown away, so a run that failed the check painted a success and moved on. The account row now says plainly that the numbers do not add up, the account keeps a sentence explaining what that means for its figures, and the run history records it. A folder run that could not import something no longer reports itself as up to date, and a status RiTrade does not recognise reads as something needing your attention rather than as a success. A file that imported but could not be moved out of your watch folder is now named, along with the part that matters: nothing needs re-importing.
- **The numbers on the delete and result screens are ones you can check.** The screen asking you to confirm a delete and the message afterwards worked out their totals separately over different sets of rows, so you could approve one figure and then be told a larger one had gone. The line saying your import was verified summed the fills it wrote and the fills it deliberately did not, then called the total landed: one real import read as 310 fills landed when 26 had. An account you ticked that has nothing in your date range now stays on the screen instead of disappearing from the one screen whose whole job is to tell you what happens to your selection. "Blocked" was always zero and is gone, a count of zero no longer renders at all, and the rows you unticked before importing are shown as their own number. The delete warning counts fills and calls them fills, and fills with no currency recorded are listed on their own rather than folded into the US dollar count at the moment you are deciding whether to delete.
- **Fills you rejected in an earlier review stay rejected.** They used to be invisible to the import preview, counted as brand new and then quietly dropped. They are now named as yours: removed by you, and importing the file again did not bring them back. A delete could also remove the note protecting a rejected fill while that fill was still stored, so the next import quietly restored something you had rejected. The note now goes only when the fill it was protecting has gone with it.
- **Clearing an account's fills no longer makes you teach RiTrade your file all over again.** Clearing an account deleted what RiTrade had worked out about reading your file along with the fills, and nothing on screen said it was going to, so the next import of the same export asked you every question again as though you had never imported it. The account stays, what RiTrade learned stays, only the fills go, and the confirm says so before you press it.
- **An account named on a ledger entry is no longer destroyed by a removal that then fails.** If one of your ledger entries recorded money moving to or from an account, removing that account failed at the last step, and on one route the fills had already gone by then, so the button appeared to do nothing at all while your data was being removed underneath it. RiTrade now checks before it removes anything, keeps everything, and tells you a ledger entry is what is holding the account. It does not yet show you which entries those are.
- **Dates read as dates.** The screen asking whether to replace trades you already have was labelling itself with the raw text older fills carry, which came out as "26 06/1 to 26 06/1", three times, once inside the option that deletes. The dates on your list of imports were stored in UTC and shown unconverted, so an import could read hours out and sit on the wrong day. Both now follow your dashboard's clock, and the trades covered are exactly the ones they always covered.
- **The import check screen shows each example once.** The sample of what RiTrade read was showing the value from your file, an arrow, and then the same value again underneath: NVDA became NVDA, Long became Long. The arrow promised something had changed when nothing had.
